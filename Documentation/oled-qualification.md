# OLED branding and F8 qualification

**Software verified** evidence covers the pure state-to-banner policy, protocol
transitions under host stubs, generated artwork reproducibility, and firmware
compilation. It does not qualify screen appearance, physical timing, button
handling, or BLE pairing on a device. No device photos are recorded here.

Generate artwork with `python3 Tools/oled_bitmaps.py`; use `--check` to compare
the checked-in `GraphicsStolo.h`, or `--preview .context/oled` to write native
resolution PBMs. Font pixels, strings and layout all live in the generator.
`bm_def` and `bm_def_lc` deliberately have identical Stolo wordmarks. Boot's
single factual attribution notice wraps onto two lines: `RNode firmware` and
`unsigned.io GPLv3`. The console page generator uses
`RNode firmware · unsigned.io · GPLv3` in its footer. Deploying that footer
requires rebuilding/flashing the console image; the prebuilt upstream console
partition is not regenerated by the firmware build (the separate F9 work).

Run `make test-host` and `make firmware-stolo-tbeam_supreme` in a sketch directory
named `RNode_Firmware`. HELLO's advisory capability byte is `0x03` in the Stolo
display build and `0x00` in the headless host fixture. The host tool exposes it
as `capabilities`, `display_present` and `enroll_window_display`.

The following remain **device qualified — pending**, to be completed by Rameen
with T-Beam Supreme photos and host-tool output attached to the PR thread:

- [ ] Boot: Stolo starting label and the full attribution are legible. Idle:
      both signed and unsigned signature states show the Stolo wordmark.
- [ ] Hold the button at power-on for 3 seconds: enrollment countdown reflects
      the 60-second protocol window. Capture the first visible value and timing
      (the window opens before display initialization; startup consumes time).
- [ ] Enroll within the window: the notice clears. Repeat without enrolling:
      expiry clears the notice and restores the radio/airtime panel.
- [ ] With an unreadable store and no window: persistent STORE ERROR / HOLD BTN /
      AT BOOT. Hold at boot: RESCUE and countdown. Explicitly run RESCUE on the
      test unit: NEW IDENTITY for 5 seconds, then the normal panel. Confirm the
      host tool observes the new identity. Rescue deliberately replaces identity.
- [ ] A simultaneous firmware/radio/config fault remains visible above each
      Stolo notice, including persistent STORE ERROR and pairing. Without a
      Stolo notice (and in plain builds), faults retain the lower-band priority.
- [ ] Pairing PIN wins over enrollment, rescue, success and store-error notices;
      six digits remain legible. Notice priority also holds with an external
      framebuffer and automatic display blanking enabled.
- [ ] HELLO on the device reports the display capability bits. Bluetooth still
      advertises RNode XXXX; the remote AP default is Stolo Node XXXX, while a
      configured SSID remains unchanged.

Photos establish the visual claims; generated previews do not replace them.
